# peal

[English](README.md) | 日本語

[![CI](https://github.com/bryutus/peal/actions/workflows/ci.yml/badge.svg)](https://github.com/bryutus/peal/actions/workflows/ci.yml)

ターミナルからデスクトップ通知を送信します。

```console
$ peal --title peal "build finished"
```

peal は、長いビルド、大きなテストスイート、時間のかかるデプロイのために作られています。
処理が終わったときに通知を出すようターミナルに伝えるので、ターミナルから目を離していられます。

## 何を解決するのか

ターミナルによって、通知の要求方法は統一されていません。
現在出回っているエスケープシーケンスは3種類あり、すべてのターミナルが同じように受け入れるわけではありません。

- **OSC 9**：フィールドが1つあります。最もサポートが広く、タイトルはありません。
- **OSC 777**：タイトルと本文があります。
- **OSC 99**：id が加わり、通知が以前のものを置き換えられます。

3つの選択肢すべてを送信することは現実的ではありません。複数の入力を受け付ける端末では、入力ごとに個別の通知がトリガーされてしまうためです。
逆に、最も網羅的なオプションだけを送信するのでは不十分です。特定の方言を完全に無視するターミナルもあれば、未入力のフィールドが含まれるシーケンスに対してはまったく出力を行わないターミナルもあるためです。
そこで、peal は事前にターミナルを識別し、要求されたデータを包含する単一の方言を選択します。

どの方言が通るかは、実行時に判定できることではありません。
ターミナルがどの方言を受け付けるかは通知されず、通知は「送信して忘れる（fire-and-forget）」方式で動作します。つまり、受信の確認やOSによる拒否の報告を行う返信は返されません。
pealは実際に観察された内容を記録して持っており、[`peal probe`](#ターミナルを追加する)がその記録を広げる役割を果たします。

## ターミナル

実際の観測結果は、 [`data/terminals.toml`](data/terminals.toml) に詳述されています。
各エントリは、ドキュメントからの転記ではなく、画面を直接見て確認したものです。

XTVERSION に応答する未登録のターミナルには、OSC 9シーケンスを送ります。
まったく識別できないターミナルにはベルを鳴らします。


## インストール

```console
$ cargo install --git https://github.com/bryutus/peal
```

## 使い方

```console
$ peal "build finished"
$ peal --title peal "build finished"
$ peal --name build "compiling"        # 同じ名前で送り直すと通知が差し替わる
$ some-long-command && peal "done"
```

通知が完全に送信された場合、何も出力されません。
本文に折り返されたタイトル、脱落した名前、または代替ベル信号など、端末が処理できないデータは、予測不可能な異常を表すため、標準エラー出力に報告されます。

ライブラリとして:

```rust
use peal::notify::{self, Notification};

notify::notify(&Notification::titled("peal", "build finished"))?;
```

## 何も出ないとき

```console
$ peal doctor
```

判定したターミナルとその根拠を報告し、それぞれの通知がこの環境でどの形になるかを示し、最後に見比べる基準となる通知を1件送ります。

まず、ターミナルの通知が有効になっているかを確認してください。
通知を許可されていないターミナルは、プログラムの内側からはpealが誤ったバイト列を送ったのと見分けがつきません。`doctor` が「通知は出ました」と告げるのではなく、出たかどうかを尋ねるのはそのためです。

## tmux の下で

peal は tmux の下でも動きますが、設定がひとつ必要です。

```console
$ tmux set -g allow-passthrough on
```

tmuxは認識しないエスケープシーケンスを転送せずにドロップしてしまいます。
pealは送信するデータをラップすることで、tmuxがそれをさらに先の端末へ渡すようにします。ただし、その設定が有効な場合にのみこのラッパーは機能します。
それがなければ、ベル音しか届かず、`peal doctor` はその旨を伝えて該当する設定名を挙げます。

## ターミナルを追加する

使っているターミナルが [`data/terminals.toml`](data/terminals.toml) に無いなら、次のコマンドで記録を作れます。

```console
$ peal probe
```

方言を順に送信し、通知が表示されたかどうかを確認してから、`data/terminals.toml`用のエントリを出力します。
その出力結果を添えて（またはそれを追加するプルリクエストを作成して）Issueを開き、どのターミナルのどのバージョンからのものかを記載してください。

tmux内での `probe` は機能しますが、出力されるエントリはより簡素になります。
tmuxが `TERM_PROGRAM` と `TERM` を自身のもので上書きしてしまうため、どちらも記録できません（レポートにもその旨が記載されます）。
tmuxの外で測定したエントリには、より多くの情報が含まれます。


何も受け付けないように見えるターミナルを報告する前に、通知の許可設定を確認してください。
通知を出さないターミナルと、出すことを許可されていないターミナルは、同じに見え `probe` はそのまま報告してしまいます。

どのようなOSであれ、どのようなターミナルであっても、追加する価値があります。
